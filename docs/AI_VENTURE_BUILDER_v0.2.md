# AI VENTURE BUILDER v0.2

## 目的

公開されている無料資産を「そのまま売る」のではなく、複数の資産を組み合わせ、誰かが最初の1円を払う可能性を検証できるMVPまで進める。

このシステムはアイデア生成器ではない。各候補に、資産の出典、ライセンス、無料運用性、需要証拠、反証、収益化、MVP受け入れ条件を紐づけ、根拠が足りない候補をBuild対象にしない。

## v0.1からの変更点

- 固定テンプレート中心から、実際に取得した資産中心の組み合わせへ変更
- 「競合がある」だけでは需要点を加算しない
- 表示価格と販売実績、募集金額と契約実績を分離
- ライセンス・費用・法務リスクをBuild Gateの必須条件に変更
- 市場証拠、反証、承認履歴を実行単位で保存
- 探索、検証、構築、公開を別工程として扱い、途中の推測を事実として扱わない
- 1位を選ぶ前にTOP5全件へ強制反証を行う
- 既存MVPは別Repository・別URLのまま固定し、Builderの改善と混ぜない

## 実行ステージ

| Stage | 内容 | 完了条件 |
| --- | --- | --- |
| 0 | Run Gate | ユーザーの明示的な起動指示を確認。定期実行ではない |
| 1 | SCOUT | GitHub、GitLab、Hugging Face、政府データ等の公開資産を取得 |
| 2 | NORMALIZE | 出典URL、取得日時、ライセンス、利用条件、費用要件を構造化 |
| 3 | FILTER | ライセンス・0円・法務・個人情報・維持負担で除外 |
| 4 | COMPOSE | 実際の資産を2〜4個組み合わせ、出力物と差別化を定義 |
| 5 | VALIDATE | 支払い、契約、求人、発注、レビュー、困りごとの一次証拠を収集 |
| 6 | SCORE | 指定の100点配点で評価。証拠の強さを上限付きで反映 |
| 7 | FALSIFY | TOP5ごとに無料代替、規約、法律、価格競争、維持負担を調査 |
| 8 | BUILD GATE | STRONG GO / GO / GO WITH MODIFICATION / NO-GOを決定 |
| 9 | BUILDER | 最初の支払いを検証できる最小MVPを実装 |
| 10 | QA | 起動、主要機能、失敗、モバイル、秘密情報、ライセンス、無料運用を確認 |
| 11 | MONETIZE | 最初の1円、価格、販売チャネル、納品方法を1つに決定 |
| 12 | HANDOFF | URL、Repository、次の操作を1つだけ提示。Kill Criteriaも記録 |

## Hard Stop

次のどれかに該当する場合は、候補を作れてもBuildしない。

1. ライセンスが不明、商用利用不可、再配布条件が不明
2. 有料API、課金GPU、VPS、有料DB、カード登録が必須
3. 需要証拠が競合ページや表示価格だけ
4. 顧客、具体的な困りごと、最初の支払単位が定義できない
5. 個人情報・機密情報の保存がMVPに必須
6. 取得元の利用規約に反する収集が必要
7. 無料代替との差分が「AIを使う」だけ
8. 法的保証、医療・金融判断、著作権侵害を自動判定する設計
9. 構築後の公開・販売・営業を人間承認なしに実行する必要がある

## 需要証拠の扱い

証拠はURL・確認日・観測内容・証拠種別を記録する。価格が表示されているだけの場合は `price_displayed` とし、売上とは扱わない。

強い順の基本ルールは以下。

1. 実際の支払い・売上
2. 契約・発注・有償案件
3. 求人・業務委託募集
4. 有料レビュー・導入事例
5. 具体的な困りごとの投稿
6. 表示価格
7. 競合の存在

競合の存在だけでは需要点を0点とする。1つのページを複数の証拠として水増ししない。

## スコアと判定

| 評価項目 | 点 |
| --- | ---: |
| 実需要 | 20 |
| 完全0円構築可能性 | 15 |
| AI自律稼働率 | 15 |
| 収益化の明確さ | 15 |
| 初収益までの速さ | 10 |
| 競争優位 | 10 |
| 実装難易度 | 5 |
| 顧客対応の少なさ | 5 |
| 拡張性 | 5 |
| 合計 | 100 |

判定の目安は、証拠不足の候補を高得点にしないため、スコアだけでなくBlockerも同時に見る。

- `STRONG GO`: 80点以上、強い需要証拠、Blockerなし、反証後も優位性が残る
- `GO`: 70点以上、最低限の需要証拠、Blockerなし
- `GO WITH MODIFICATION`: 需要はあるが、対象・価格・MVP範囲などの修正が必要
- `NO-GO`: 需要証拠不足、無料運用不可、ライセンス不明、または反証で優位性が消える

## 保存する実行成果物

実行ごとに、同じRun IDで次を保存する。

- `run-manifest.json`: 起動指示、日時、費用条件、使用ソース、エラー
- `assets.json`: 取得資産、出典、ライセンス、無料要件、更新日時
- `hypotheses.json`: 組み合わせ、顧客、問題、出力物、収益化
- `evidence.json`: 需要証拠と確認日、表示価格と販売実績の区別
- `falsification.json`: TOP5の反証結果
- `decision.json`: TOP3、1位、判定、Blocker、承認ポイント
- `build-brief.md`: MVP仕様、受け入れ条件、価格、納品方法
- `qa.md`: テスト結果、既知の制限、公開前チェック

## 人間承認ポイント

調査・コード作成・ローカルテストは自動で進める。次の操作だけは停止して承認を求める。

- GitHubログインやOAuth接続
- RepositoryやWebサイトの公開
- 決済サービスやアフィリエイト申請
- 外部への営業・DM・メール送信
- 契約・有料契約・金銭の支払い
- 個人情報や秘密情報を扱う設計
